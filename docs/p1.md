日期：2026-11-23。状态：核心实现已完成，真实模型与浏览器端到端验收待补。P0 未全部验收；按用户明确指示开始 P1，遗留项继续保留在主计划。

## 使用方式

在根目录 `.env` 填写模型配置。已有文件已追加缺失项，不覆盖原有值；示例见 [.env.example](../.env.example)。不要将真实 Key 发到聊天或提交到 Git。

```dotenv
LLM_API_KEY=在本机填写真实Key
LLM_BASE_URL=https://api.openai.com/v1
LLM_MODEL=gpt-4.1-mini
LLM_TIMEOUT_SECONDS=20
LLM_MAX_OUTPUT_TOKENS=1600
AGENT_TIMEZONE=Asia/Hong_Kong
AGENT_CONFIRMATION_TTL_SECONDS=900
```

接口需要兼容 `POST {LLM_BASE_URL}/chat/completions`、Bearer Key、`response_format: {type: json_object}`、`max_tokens` 及标准 `choices/finish_reason` 响应。其他服务商填写自己的地址和模型名；这里没有自动探测或降级到未批准供应商。Azure / Responses API 等不同协议需要额外适配。HTTP 仅允许 loopback 本地端点，其余要求 HTTPS。

Key 使用 SecretStr，仅由后端模型适配器使用；不使用 `VITE_` 前缀。Compose 的 BFF 环境已改为显式白名单，不再把全部 `.env` 注入 BFF 容器。应用运行时不允许用户修改模型地址。缺 Key 时普通报销表单仍可用，Agent 返回明确配置提示，不偷偷使用假模型。

```powershell
pnpm install --frozen-lockfile
uv sync --locked --directory services/backend
pnpm db:migrate
pnpm dev
```

本次已在本地开发数据库应用 `0002_agent_runs`。其他环境仍需运行迁移命令；不要修改 `0001`。配置变化后重启 Python 后端。

如果 `POST /api/v1/agent/runs` 返回 404，先查看 `http://127.0.0.1:8000/openapi.json` 是否包含此路径。后端入口当前 `reload=False`，旧进程不会自动加载新路由；代码更新后需要重启。使用 `pnpm dev` 时，应在原终端 Ctrl+C 后重新运行整个 `pnpm dev`，因为其中一个服务退出会联动停止其他服务。分开运行 `pnpm dev:backend`、`pnpm dev:bff`、`pnpm dev:web` 则可独立重启。路由加载后，匿名请求应返回 401，而不是 404。

打开 `http://localhost:5173/assistant`，登录员工小林后输入：

> 昨天成都到上海的高铁票286元，出差拜访客户。

信息不完整时补充；核对右侧的标题、用途、日期、类别、说明和金额，再点“确认创建”。发送修改会先撤销旧确认，再重新提取。仅在对话里说“确认”不会写入。创建成功后通过链接打开真实草稿。

成功取得 run 后 URL 包含 `?run=<id>`。页面顶部“我的助手任务”分页列出当前用户的任务，可切换未完成、已完成和已取消的任务；任务短编号用于区分同名申请。每项任务对应一次独立的报销草稿创建，完成后点击“新任务”处理下一笔，不覆盖旧任务。

在同一浏览器标签页内，切换“新建报销 / 我的报销”再返回助手，会恢复上次选中的任务；新浏览器会话默认读取服务端最新任务。点击“新任务”使用 `?new=1` 明确保持空白新任务，避免被自动恢复替换。浏览器 sessionStorage 只按企业 / 用户保存选中的任务 ID 或新任务标记，消息和预览从数据库读取；禁用浏览器存储时仍可从服务端列表选择任务。未发送的输入不自动保存。

其他用户和财务均无权读取这份私人 Agent 对话。打开历史任务不创建财务数据，也不延长确认期限；过期预览需补充消息重新生成，再明确确认。不要把“新任务”当成取消旧任务：已接受确认的写入仍可能完成，先刷新原任务核实。

## 实现边界

- LangGraph 执行有界的理解与确定性字段校验，每轮最多一次模型调用；持久服务处理消息、预览、确认、取消和工具执行。
- `agent_runs` 保存候选、原始消息、每轮候选快照及来源消息 ID / Prompt 版本、版本号、确认期限和结果单号。快照用于追溯模型在哪轮提出候选值，不等于该值已获业务核实。
- 每条用户消息有稳定日期锚点；重试使用原锚点，新一轮消息按任务时区生成新锚点；已有绝对日期不应被重新解释。
- 明细金额用十进制字符串严格转换为整数分；缺项与非法金额进入澄清，财务服务再次校验并计算总额。
- 确认绑定当前用户、run、内容哈希、预览版本、服务端 UUID 与有效期。修改、取消、过期或跨用户确认均不能创建。
- 确认先用版本条件更新领取操作，再以稳定幂等键调用唯一工具 `create_expense_draft`。工具复用 `finance.service.create_expense`；返回值经过 schema 校验与字段裁剪。
- 财务提交后、任务结果保存前发生故障时保持 `executing`；重试原确认以同一键取得业务结果。执行中禁止修改 / 取消，不把未知结果宣称为失败或成功。
- BFF 校验请求 DTO、任务列表摘要及成功响应的消息、状态、预览金额与合计。当前模型 I/O timeout 可配置 1–60 秒，BFF 请求 timeout 60 秒，前端消息 timeout 50 秒；较高模型超时配置可能使浏览器先超时，此时通过任务历史核验状态。统一总截止时间与后台任务生命周期仍在 P2 实现。
- 每个任务最多 40 条对话消息；单条用户输入 2000 字符，模型输出 200–4000 token 可配置，模型响应最多 128 KB。没有无限工具 / 修复循环，也没有 SDK 自动重试。
- 本地日志只记录请求 / run / operation / 单号 / 工具 / Prompt 版本等操作元数据。P1 显式关闭 LangSmith 原始上下文自动上传，平台接入留待数据治理确认。

这不是 P2 的 PostgreSQL LangGraph checkpointer 或持久 worker。没有自动重领任务、人工审批、RAG、长期记忆、MCP，也没有宣称跨模型与数据库“恰好执行一次”。当前是有持久快照与业务幂等保护的 P1 实现。

## 测试与评测

```powershell
uv run --locked --directory services/backend pytest -q -rs
pnpm --filter @enterprise/bff test
pnpm typecheck
pnpm build
```

新增测试覆盖澄清时零写入、有效确认、重复确认、旧确认失效、模型失败时先撤销旧预览、消息去重、跨用户 / 租户、过期 / 篡改确认、财务提交后响应丢失、慢模型期间并发更新、模型契约及配置边界。真实 PostgreSQL 另验证两个独立 Session 并发确认只产生一张主单和一条创建审计。

参考样例校验不调用模型或财务工具：

```powershell
uv run --locked --directory services/backend python -m enterprise_agent.agent.evaluate --output ../../work/p1-reference-eval.json
```

30 条虚构样例位于 `services/backend/evals/expense_cases.json`，报告 mode 为 `reference-validation-only`。这是参考提取结果的确定性验证，不是自然语言提取准确率，也不是独立保留集。

填好 Key 后先做 3 条真实模型验证，再根据费用扩大到 30 条：

```powershell
uv run --locked --directory services/backend python -m enterprise_agent.agent.evaluate --live --limit 3 --output ../../work/p1-live-eval.json
```

此命令仅调用模型提取和校验，不创建报销单。完整端到端仍需浏览器：先缺用途追问，再补用途生成预览；修改金额后旧确认失效；明确确认创建；刷新 / 重试仍为同一单号；切换用户无法访问任务和草稿。

真实 HTTP 链路也提供了可重复的本地 harness（要求先构建 BFF，且独立测试库 `enterprise_agent_p0_test` 已存在）：

```powershell
uv run --locked --directory services/backend python evals/http_flow.py
```

它启动临时 BFF / Python / 本地模型替身，在随机隔离 schema 中迁移并执行真实 HTTP 登录、澄清、预览、确认、重试及越权测试，结束后停止进程并清理 schema。不使用真实模型 Key，不写入演示业务表。报告位于 `work/p1-http-flow.json`。
